# Chat copy controls

Every completed answer has a whole-response Copy action. Fenced Markdown blocks
have an independent Copy button that copies only the raw block text, without
fences, language labels, explanations or other blocks. Unicode, code and line
breaks are preserved; only the parser-added terminal newline is removed.
Existing stored answers containing fenced blocks receive the controls on render.

When a user asks to copy a specific part, the text assistant is instructed to
place only that content in a fenced block. `copy-before` (or ordinary `text`)
places the control above it; `copy-after` places it below. These are supported
rendering conventions, not arbitrary executable UI generated by the model.
Normal answers remain readable prose; code and reusable prompts, musical styles
or lyrics can be separated into copyable blocks. The model's format compliance
is not guaranteed; the whole-response Copy action remains available regardless.
Raw HTML remains disabled in Markdown. Clipboard content is plain text.

The shared web/PWA Copy control first tries the browser Clipboard API, then the
legacy local selection copy API if blocked/unavailable. If neither succeeds,
it opens an accessible dialog with the exact text selected for manual device
copy. It does not report success on failure, request AI generation, debit
credits, transmit copied content or alter saved messages. Copy success is
shown briefly with a check mark and localized feedback.

Offline browser tests cover exact block/whole-answer copying, before/after
placement, code treated as text, denied Clipboard API fallback, total failure
manual selection, mobile layout and unchanged wallet/job-call count. A grounded
research/file/location regression also exercises the same Markdown renderer.
No paid Google generation is used for verification.
